

## 1. Kubernetes Event란?

K8s Event는 **“클러스터에서 무슨 일이 벌어졌는지”를 설명하는 메타 이벤트 로그**야.

(애플리케이션 로그 ❌ / 상태 변화 & 제어 플레인 이벤트 ⭕)



### 공통 구조 (핵심 필드)

- reason : 왜 발생했는지 (Scheduling, FailedMount 등)
- type : Normal / Warning
- involvedObject
  - kind (Pod, Node, Deployment, PVC, Ingress 등)
  - name
  - namespace
- message : 사람이 읽는 설명
- eventTime / firstTimestamp / lastTimestamp
- count : 동일 이벤트 반복 횟수



## 2. K8s Event로 확인 가능한 것들 (현업 기준)

아래는 **“이것만 봐도 장애 원인의 70%는 잡는다”** 리스트야.



### **🔹 Pod / 워크로드**

- Pod Scheduling 실패

  - FailedScheduling (리소스 부족, 노드 셀렉터, taint)

- Image 문제

  - ErrImagePull, ImagePullBackOff

- Crash

  - BackOff, CrashLoopBackOff

- Probe 실패

  - Unhealthy (liveness/readiness)

  

### **🔹 Node**

- 노드 상태 변화
  - NodeNotReady, NodeReady
- 디스크/메모리 압박
  - NodeHasDiskPressure
  - NodeHasMemoryPressure
- 노드 재부팅/네트워크 이슈

👉 **클러스터 전체 장애 조짐**



### **🔹 Storage (PVC / PV)**

- PVC 바인딩 실패
  - FailedBinding
- Mount 실패
  - FailedMount
  - Unable to attach or mount volumes

👉 **AKS / CSI / NFS / Azure File 쓰면 필수**



### 🔹 Networking / Ingress

- Ingress 컨트롤러 에러
- Service 엔드포인트 생성/삭제
- LoadBalancer 할당 실패

👉 **외부 접속 안 될 때 제일 먼저 보는 영역**



### 🔹 Control Plane / 기타

- HPA 스케일 이벤트
- ConfigMap / Secret 변경
- Job / CronJob 실패



## 3. K8s Event 수집 아키텍처 (OpenSearch 기준)



**정답 루트 하나만 기억하면 됨**

```
Kubernetes Event
   ↓
Fluent Bit (kubernetes_events)
   ↓
OpenSearch
   ↓
OpenSearch Dashboards
```

> ❗ 이벤트는 **kube-apiserver에서만 발생**

> → DaemonSet 말고 **1개 Fluent Bit만 있어도 충분**





## 4. Fluent Bit – K8s Event 수집 핵심

(개념만, 설정은 다음 단계에서 같이 짜도 됨)

### **입력**

- kubernetes_events input
- Event API 직접 구독

### **출력**

- OpenSearch (index 분리 추천)



### **인덱스 예시**

```
k8s-events-YYYY.MM.DD
```





## 5. OpenSearch Dashboards – K8s 전용 대시보드



### **결론부터 말하면**

👉 **“별도 플러그인 설치는 필요 없음”**

👉 대신 **Index Pattern + Dashboard만 만들면 됨**

(OpenSearch Dashboards는 Kibana 호환 개념)



### **📊 반드시 만들 대시보드 구성**



#### **① Overview**

- Event Type 비율 (Normal vs Warning)
- 최근 24h 이벤트 수 추이
- Namespace Top N (이벤트 기준)



#### **② Pod / Workload Events**

- reason.keyword Top (CrashLoopBackOff, FailedScheduling 등)
- Namespace + Pod 기준 테이블
- Warning 이벤트 필터 뷰



#### **③ Node Events**

- Node별 Warning 이벤트 수
- Node 상태 변화 타임라인



#### **④ Storage / Network**

- PVC / PV 관련 이벤트
- Ingress / Service 이벤트



### **🎯 필수 필드 매핑 (Dashboards 편의)**

Fluent Bit에서 가능하면 이런 필드 형태로 정규화해두면 좋아:

```
{
  "@timestamp": "...",
  "event.type": "Warning",
  "event.reason": "FailedScheduling",
  "k8s.namespace": "opensearch",
  "k8s.kind": "Pod",
  "k8s.name": "opensearch-dashboards-xxx",
  "message": "0/3 nodes are available..."
}
```
