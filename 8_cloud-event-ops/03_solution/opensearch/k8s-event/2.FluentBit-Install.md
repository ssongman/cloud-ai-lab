



# 1. 개요

“K8s 이벤트만” OpenSearch로 보내는 Fluent Bit Helm 설치 가이드

(이미 OpenSearch는 k8s 위에 있고, opensearch-dashboards도 설치한 상태라고 가정)



# 2. 권한 부여



K8s 이벤트는 네임스페이스별로도 존재하지만, Fluent Bit kubernetes_events 인풋은 보통 **클러스터 전체 이벤트를 list/watch** 하려다 보니 **ClusterRole/ClusterRoleBinding** 이 필요

만약 권한이 없으면 아래 에러 발생

> system:serviceaccount:monitoring:fluent-bit-events 가 **cluster scope에서 events 리소스를 list/watch 할 권한이 없음** → RBAC 문제(403)



## **1) RBAC 추가 적용**

ClusterRole + ClusterRoleBinding 적용



```sh
$ cat <<'EOF' | kubectl apply -f -
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: fluent-bit-events
rules:
  - apiGroups: [""]
    resources: ["events", "pods", "namespaces", "nodes"]
    verbs: ["get", "list", "watch"]
  - apiGroups: ["events.k8s.io"]
    resources: ["events"]
    verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: fluent-bit-events
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: fluent-bit-events
subjects:
  - kind: ServiceAccount
    name: fluent-bit-events
    namespace: monitoring
EOF



```

> 왜 pods/namespaces/nodes도 줬냐면: 이벤트가 “어떤 오브젝트에 대한 이벤트인지” 메타를 붙일 때 같이 조회하는 경우가 많아서야. (최소 권한으로도 충분히 안전한 편)



## **2) 권한 확인 (바로 검증)**



```

kubectl auth can-i list events --as=system:serviceaccount:monitoring:fluent-bit-events
kubectl auth can-i watch events --as=system:serviceaccount:monitoring:fluent-bit-events
kubectl auth can-i list events.events.k8s.io --as=system:serviceaccount:monitoring:fluent-bit-events

yes
yes
yes

```

전부 yes가 떠야 정상.

## 2) Fluent Bit를 “Event 전용”으로 설치

> 핵심: kind: Deployment + kubernetes_events input + OpenSearch output



#### NS

```
kubectl create ns monitoring

```



아래를 그대로 실행해봐:

```sh
$ cat <<'EOF' | helm -n monitoring upgrade --install fluent-bit-events fluent/fluent-bit \
    -f -
kind: Deployment
replicaCount: 1

serviceAccount:
  create: true
  name: fluent-bit-events

rbac:
  create: true

# Fluent Bit 자체 설정
config:
  inputs: |
    [INPUT]
        Name              kubernetes_events
        Tag               k8s.events

  filters: |
    # 필요 시 필드 정리/정규화 (최소만)
    [FILTER]
        Name              modify
        Match             k8s.events

  outputs: |
    [OUTPUT]
        Name              opensearch
        Match             k8s.events
        Host              opensearch-cluster-master.opensearch.svc
        Port              9200
        Index             k8s-events-%Y.%m.%d
        
        # 중요: OpenSearch/ES 7+에서 _type 제거
        Suppress_Type_Name    On

        # (선택) Logstash format을 쓰고 싶으면 유지해도 되지만,
        # 문제 단순화를 위해 일단 Off 권장
        Logstash_Format        Off
        HTTP_User         admin
        HTTP_Passwd       Opensearchpass123!
        TLS               On
        TLS.Verify        Off

resources:
  requests:
    cpu: 100m
    memory: 128Mi
  limits:
    cpu: 300m
    memory: 256Mi
EOF


```

> ⚠️ 주의



- > Host는 **OpenSearch 서비스 DNS**로 맞춰야 해. (예: opensearch-cluster-master.opensearch.svc 같은 형태일 수도 있음)

- > OpenSearch 인증/비번이 다르면 HTTP_User/HTTP_Passwd 수정.

upgrade 했다면 권한부여 다시 해야 함.

# 4. Opensearch index 확인



```sh
$ Get _cat/indices?v


$ GET _cat/indices/k8s-events*?v
health status index                 uuid                   pri rep docs.count docs.deleted store.size pri.store.size
yellow open   k8s-events-2026.02.08 28wXUPhsRKeoU4BE9n1D9Q   1   1         23            0     42.2kb         42.2kb

```

* yellow 로 나오는 이유
  * 이 인덱스는 **Primary shard 1개 + Replica shard 1개**로 생성됐는데,
  * 지금 OpenSearch 클러스터가 노드 1개라서
  * Replica shard를 **같은 노드에 둘 수 없기 때문에** 할당이 안 된 상태임
* 참고
  * 🟢 **green**: primary + replica 모두 정상 할당
  * 🟡 **yellow**: **primary는 정상**, replica만 미할당
  * 🔴 **red**: primary도 미할당 (데이터 위험)





만약 index 가  안 나오면

- > Fluent Bit output Host/인증/Index 이름 다시 확인

- > Fluent Bit 로그에 flush / HTTP status=200 있는지 확인







# 5.  OpenSearch index 확인

Fluent Bit가 인덱스를 잘 밀어 넣고 있어도 OpenSearch Dashboards는 인덱스를 “자동 인식”하지 않는다.



## 1) Index Pattern 생성

> OpenSearch Dashboards는 **“Index Pattern”을 수동으로 만들어야 시각화 가능**



### 경로

```
OpenSearch Dashboards
 → Management
   → Dashboards Management
     → Index Patterns
```



### 생성값

- **Index pattern name**:

```
k8s-events-*
```



- **Time field**:

```
@timestamp
```

생성 클릭.



## 2) Discover에서 바로 확인

```
OpenSearch Dashboards → Discover
```



### 추천 필터

- event.type : "Warning"
- event.reason : "ImagePullBackOff"
- kubernetes.namespace_name : default

(필드명은 실제 들어온 이벤트 JSON 기준으로 보이면 그걸 쓰면 됨)





## 3) 만약 Index Pattern 메뉴가 안 보인다면?

OpenSearch Dashboards 버전에 따라 메뉴명이 조금 다르다.

- **Management → Index Patterns**
- 또는 **Stack Management → Index Patterns**
- 또는 **Dashboards Management → Index Patterns**



> 권한 이슈로 안 보이면 admin 계정으로 로그인했는지도 확인.





## 4) 추천: 이 단계에서 꼭 해두면 좋은 것



### (1) 필드 Refresh

Index Pattern 만든 뒤:

```
Index Pattern → Refresh field list
```

→ 새 필드가 바로 보임



### **(2) 시간 범위**

Discover 우측 상단:

- Last 15 minutes → Last 1 hour 또는 Last 24 hours

K8s Event는 금방 사라지는 경우가 많아서 이거 안 맞추면 “없어 보임”.
